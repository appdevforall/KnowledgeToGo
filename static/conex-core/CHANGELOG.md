# conex-core (content-exchange core) - changelog

One line per version, newest first. Every REST-facing change bumps `conex_core.VERSION` (reported by
`GET /v1/version`, and written into the `[conex_core]` section of iiab.ini by the conex_core Ansible
role), so this file is the human record of what each bump enables. Keep entries short:
`version - change (TICKET)`.

- **0.4.1** - Share moves Kolibri channels with rsync too, with no tar and no staging (K2GO-577). The sender module holds the channel DB and the available content files, in place. The receiver pulls the DB into a work dir and the files straight into Kolibri storage (a file that exists is skipped: its name is its md5; temp and kept partial files stay in `/library/.conex-partial`), then links them with `importchannel disk`, `scanforcontent --channel-import-mode none` and `importcontent disk` on a manifest of the nodes that arrived. A drop keeps the received files and a retry continues. (K2GO-577)
- **0.4.0** - Share moves ZIMs with rsync (K2GO-577). While a share session is open, the box runs an rsync daemon (`CONEX_SHARE_RSYNC_PORT`, default 9873, 0 = off) with one read-only module per shareable item, password = the session token; the last session close stops it. The share manifest adds `rsync: {port, module}` per such item. `POST /v1/import/item` with `source: {host, port, module, token}` instead of `payloadPath` pulls the item straight into place: no staging copy, a drop or a cancel keeps the bytes in `/library/.conex-partial` and the next pull resumes and verifies the whole file. `POST /v1/share/{id}/progress` takes the receiver's per-item progress (keeps the session fresh, marks `done` items delivered); `GET /v1/share/{id}/progress` is the sender's view. Kolibri and Calibre still share over the HTTP fetch. (K2GO-577)
- **0.3.5** - Kiwix counts as installed only when kiwix-serve is present, not just the zims dir, so a library that cannot open ZIMs answers NO_APP and does not import them. (K2GO-574)
- **0.3.4** - import becomes a long operation like export: POST /v1/import/item now STARTS the ingest and returns an opId, the client polls GET /v1/import/status/{op}, and DELETE /v1/import/{op} cancels, so a 35-141 s Kolibri import no longer times out at the dash-node/nginx relay. A shared liveness watchdog supervises the Kolibri import and export CLIs by byte and CPU progress (no fixed timeout; the window is relative to the task) and names a signal-9 exit as a likely out-of-memory kill. (K2GO-376)
- **0.3.3** - observability: log every error response and uncaught handler exception to stdout (the supervisor captures it to /var/log/conex-core.log), and line-buffer stdout/stderr in __main__ so output reaches the log while the server runs forever, so a failed import or share leaves a box-side trace; an uncaught error now returns a 500 JSON instead of dropping the connection. (K2GO-376)
- **0.3.2** - /v1/import/item returns 507 (not 422) when a stage runs out of disk (adapters tag it code "no_space"), so the front stops the run with a space message; /v1/export/prepare drops the proot-based free-space preflight too (same false-507 as import), failing cleanly during staging instead. (K2GO-376)
- **0.3.1** - /v1/import/item drops the free-space preflight (proot under-reports free space, so the 507 false-rejected valid imports); a real ENOSPC during ingest now fails cleanly as 422. (K2GO-376)
- **0.3.0** - /v1/share gate: a token-scoped, two-lifetime share session (ephemeral connection vs durable session) over a scoped item set, reusing the export op per item, for granular wireless Share. (K2GO-376)
- **0.2.0** - export as a prepare/poll/fetch long operation, so a large Kolibri channel stages without timing out the client. (K2GO-507)
- **0.1.0** - initial content-exchange core: read (list + identity), export, import and delete over /v1 across Kiwix, Kolibri and Calibre. (K2GO-427)
